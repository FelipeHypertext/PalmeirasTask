1 O que faz o isset() e onde ele é usado no projeto? ▼

isset() verifica se uma variável existe e se seu valor não é null. Retorna true se existir e não for nula, false caso contrário.

No projeto é usado em três situações principais:

  • Verificar se o usuário está logado: isset($_SESSION["id_usuario"])
  • Verificar se chegou dados de formulário: isset($_POST["email"])
  • Verificar se existe cookie salvo: isset($_COOKIE["palmeiras_token"])
// Se o usuário está logado:
if (isset($_SESSION["id_usuario"])) {
    // usuário autenticado
}

// Se o formulário foi enviado:
if ($_SERVER["REQUEST_METHOD"] === "POST" && isset($_POST["email"])) {
    // processa login
}
Diferença de isset() para empty(): isset("") = true (existe mas é vazia), empty("") = true (é vazia). No projeto usamos isset() para checar existência.
2 Para que serve o session_start()? Por que fica no topo do arquivo? ▼

session_start() inicializa ou retoma a sessão PHP. Ele faz duas coisas:

  • Lê o cookie PHPSESSID enviado pelo navegador
  • Carrega na variável $_SESSION os dados salvos no servidor para aquela sessão

Precisa ficar antes de qualquer saída HTML porque ele envia um cabeçalho HTTP (Set-Cookie: PHPSESSID=...). Cabeçalhos só podem ser enviados antes do corpo da resposta. Se vier depois de um echo ou de qualquer espaço em branco, o PHP lança o erro "headers already sent".

// index.php — PRIMEIRO bloco do arquivo
<?php
declare(strict_types=1);
session_start();       // ← aqui, antes de tudo
session_regenerate_id(true);
3 O que é session_regenerate_id(true) e por que usamos isso? ▼

Cria um novo ID de sessão e descarta o antigo. O parâmetro true apaga o arquivo de sessão antigo no servidor.

Por que é necessário? Para prevenir o ataque chamado Session Fixation: quando um atacante descobre o ID de sessão de um usuário antes do login e depois usa esse mesmo ID para se passar por ele depois que ele loga. Regenerando o ID no login, o ID antigo que o atacante conhecia para de funcionar.

// Usado no login bem-sucedido
session_regenerate_id(true);
$_SESSION["id_usuario"]   = $usuario->getId();
$_SESSION["nome_usuario"] = $usuario->getNome();
$_SESSION["cargo"]        = $usuario->getCargo();
4 O que é CSRF? Como está implementado aqui? ▼

CSRF (Cross-Site Request Forgery) é um ataque onde um site malicioso força o navegador da vítima a fazer uma requisição ao seu sistema sem que ela saiba. Por exemplo: a vítima está logada no sistema e abre um link armadilha que envia um formulário POST para deletar dados.

Defesa com token CSRF:

  • Na primeira requisição, gera-se um token aleatório e o salva na sessão
  • Todo formulário inclui esse token em um campo oculto
  • Ao receber o POST, o servidor compara o token do formulário com o da sessão
  • Se não bater, rejeita a requisição
// 1. Gera o token (index.php)
if (!isset($_SESSION["csrf_token"])) {
    $_SESSION["csrf_token"] = bin2hex(random_bytes(32));
}

// 2. Coloca no formulário (View)
<input type="hidden" name="csrf" value="<?= $_SESSION['csrf_token'] ?>">

// 3. Valida no Controller
$token = $_POST["csrf"] ?? "";
if (!hash_equals($_SESSION["csrf_token"], $token)) {
    die("Falha no acesso");
}

Por que hash_equals() e não ===? O operador === para de comparar ao encontrar o primeiro caractere diferente (timing attack). hash_equals() sempre compara o tempo inteiro, impedindo que um atacante descubra o token letra por letra medindo o tempo de resposta.

5 O que faz password_hash() e password_verify()? Por que PASSWORD_ARGON2ID? ▼

password_hash() transforma a senha em um hash criptográfico. Nunca salvamos a senha pura no banco — se o banco vazar, o atacante só tem o hash.

password_verify() compara uma senha digitada com o hash salvo. Não é possível "descriptografar" o hash — ele recalcula e compara.

// Cadastro: guarda o hash no banco
$senhaHash = password_hash($senha, PASSWORD_ARGON2ID);
// Resultado: "$argon2id$v=19$m=65536,t=4,p=1$..."

// Login: compara senha digitada com hash do banco
if (password_verify($senhaDigitada, $usuario->getSenha())) {
    // senha correta
}

Por que ARGON2ID? É o algoritmo mais moderno e seguro disponível no PHP 8. É resistente a ataques por GPU e por hardware especializado (ASIC). O bcrypt (padrão antigo) é mais vulnerável a esses ataques.

7 O que faz o prepare()? Por que ele previne SQL Injection? ▼

SQL Injection é quando um usuário malicioso coloca comandos SQL dentro de um campo do formulário para manipular o banco. Exemplo: digitar ' OR '1'='1 no campo de senha para logar sem senha.

prepare() envia a estrutura da query para o banco antes dos dados. O banco já sabe o que é SQL e o que são dados — nunca confunde os dois.

// ERRADO — vulnerável a SQL Injection
$sql = "SELECT * FROM usuarios WHERE email = '$email'";

// CERTO — usando prepare() + bindValue()
$sql = $pdo->prepare("SELECT * FROM usuarios WHERE email = ?");
$sql->execute([$email]);
// O banco trata $email como DADO puro, nunca como SQL

Os ? ou :nome são chamados de placeholders — espaços reservados onde os dados serão inseridos com segurança.

8 O que é bindValue()? Qual a diferença para bindParam()? ▼

bindValue() vincula um valor ao placeholder. Copia o valor naquele momento. bindParam() vincula uma referência à variável — se a variável mudar antes do execute(), o novo valor é usado.

// bindValue — copia o valor agora
$sql->bindValue(":nome",  $usuario->getNome(),  PDO::PARAM_STR);
$sql->bindValue(":email", $usuario->getEmail(), PDO::PARAM_STR);
$sql->execute();

// PDO::PARAM_STR = string, PDO::PARAM_INT = inteiro
// Isso garante que o tipo do dado está correto

No projeto usamos sempre bindValue() porque chamamos getters diretamente (retornam valores, não referências).

9 O que é fetchAll(PDO::FETCH_ASSOC) e fetch(PDO::FETCH_ASSOC)? ▼

Após executar um SELECT, precisamos ler os resultados:

  • fetchAll() — retorna todas as linhas de uma vez em um array
  • fetch() — retorna apenas a próxima linha (ou false se não houver mais)
  • PDO::FETCH_ASSOC — cada linha vira um array associativo com chaves igual ao nome das colunas
// fetchAll — para listar vários registros
$res = $sql->fetchAll(PDO::FETCH_ASSOC);
// $res = [ ["id"=>1,"titulo"=>"..."], ["id"=>2,...] ]

// fetch — para buscar um único registro
$d = $sql->fetch(PDO::FETCH_ASSOC);
// $d = ["id"=>1, "email"=>"admin@palmeiras.com", ...]
if (!$d) return null; // nenhum resultado
10 O que é spl_autoload_register e como o autoload funciona aqui? ▼

Sem autoload, teríamos que escrever um require_once para cada classe usada. spl_autoload_register registra uma função que é chamada automaticamente sempre que o PHP tenta usar uma classe ainda não carregada.

// Autoload.php
spl_autoload_register(function ($namespace) {
    $arquivo = __DIR__ . DIRECTORY_SEPARATOR
        . str_replace(['App\\', '\\'], ['', DIRECTORY_SEPARATOR], $namespace)
        . ".php";
    if (file_exists($arquivo)) { require_once $arquivo; }
});

Exemplo de conversão:

  • App\Model\Usuario → remove "App\" → Model\Usuario → troca "\" por "/" → model/Usuario.php
  • App\Dal\UsuarioDao → dal/UsuarioDao.php
  • App\Controller\AuthController → controller/AuthController.php

13 O que é uma classe abstract? Por que os DAOs são abstratos? ▼

Uma classe abstrata não pode ser instanciada diretamente — não dá para fazer new UsuarioDao(). Serve de modelo ou container de métodos estáticos relacionados.

No projeto, os DAOs são abstract porque:

  • Todos os métodos são static — não precisamos de objetos
  • Impede que alguém crie uma instância desnecessária
  • Deixa claro que é uma classe utilitária, não uma entidade
abstract class UsuarioDao {
    public static function cadastrar(Usuario $usuario): int { ... }
    public static function listar(): array { ... }
}

// Uso: diretamente na classe, sem instanciar
$lista = UsuarioDao::listar();
14 Por que o construtor dos Models é private? O que é o padrão Factory Method? ▼

O construtor private function __construct() {} impede que alguém crie um objeto assim:

$u = new Usuario(); // ERRO — construtor é private

A criação é obrigada a passar pelo método criar(), que é o Factory Method. Vantagem: o método criar() chama os setters com validação antes de preencher as propriedades.

public static function criar(?int $id, string $nome, ...): static {
    $usuario = new static();   // só a própria classe pode chamar new
    $usuario->setNome($nome);  // setter valida: nome não pode ser vazio
    $usuario->setCpf($cpf);    // setter valida: CPF deve ter 11 dígitos
    return $usuario;
}

Assim, um Usuario sempre nasce válido — nunca existe um objeto com nome vazio ou CPF errado.

15 O que são cookies? Como o "lembrar-me" foi implementado? ▼

Cookies são pequenos arquivos de texto que o servidor manda para o navegador e o navegador devolve em toda requisição futura. Ao contrário da sessão (que some quando o navegador fecha), cookies persistem pelo tempo configurado.

Implementação do lembrar-me:

  • Usuário marca "lembrar-me" no login
  • Geramos um token aleatório, salvamos o hash no banco e o token puro no cookie
  • Nas próximas visitas, se encontrar o cookie, busca o hash no banco e loga automaticamente
// Gera token e salva hash no banco
$tokenRaw  = bin2hex(random_bytes(32)); // token que vai no cookie
$hashToken = hash("sha256", $tokenRaw);    // hash que fica no banco
UsuarioDao::atualizarToken($id, $hashToken);

// Envia cookie por 30 dias
$expira = time() + (30 * 24 * 60 * 60);
setcookie("palmeiras_token", $tokenRaw, $expira, "/", "", false, true);

// Na próxima visita: verifica o cookie
if (isset($_COOKIE["palmeiras_token"])) {
    $hash    = hash("sha256", $_COOKIE["palmeiras_token"]);
    $usuario = UsuarioDao::buscarPorToken($hash);
    if ($usuario !== null) { // loga automaticamente }
}

Salvamos o hash no banco (não o token puro) para que se o banco vazar, o atacante ainda não consiga usar o valor diretamente.

17 O que é header("Location: ...") e por que vem seguido de exit? ▼

header("Location: url") envia um cabeçalho HTTP de redirecionamento (código 302). O navegador recebe e carrega a nova URL.

O exit (ou exit;) é obrigatório logo após. Sem ele, o PHP continuaria executando o código abaixo do header — inclusive poderia mostrar dados protegidos para usuários não autorizados antes do navegador concluir o redirecionamento.

// Redireciona após login bem-sucedido
header("Location: ./");
exit; // SEMPRE após header Location

// Protege página privada
if (!$autenticado && !in_array($page, $paginasPublicas)) {
    header("Location: ./?p=login");
    exit;
}
18 O que faz htmlentities() e trim()? Por que são importantes? ▼

trim() remove espaços em branco do início e do fim de uma string.

htmlentities() converte caracteres especiais HTML em entidades seguras. Isso previne XSS (Cross-Site Scripting) — quando um atacante injeta código HTML/JavaScript nos campos do formulário.

// Sem proteção — XSS possível
// Usuário digita: <script>alert('hackeado')</script>
// Se exibir direto, executa o JavaScript!

// Com htmlentities — converte para texto inofensivo
htmlentities("<script>alert('xss')</script>");
// resultado: "&lt;script&gt;alert('xss')&lt;/script&gt;"
// exibe o texto na tela, mas não executa
// Functions.php — usada em todo input do usuário
public static function preparaTexto(string $texto): string {
    return trim(htmlentities($texto));
}
19 O que é usort() com arrow function? Como a ordenação funciona? ▼

usort() ordena um array usando uma função de comparação personalizada. A função recebe dois elementos e deve retornar:

  • Negativo: se o primeiro vem antes
  • Zero: se são iguais
  • Positivo: se o segundo vem antes

O operador <=> (spaceship) já retorna -1, 0 ou 1 automaticamente.

// TarefaController — ordenação dinâmica
$ordem = match($_GET["order"] ?? "") {
    "titulo" => "getTitulo",
    "status" => "getStatus",
    "prazo"  => "getPrazo",
    default  => "getId"
};

usort($tarefas, fn($a, $b) => $a->{$ordem}() <=> $b->{$ordem}());
// $a->getId() <=> $b->getId() quando order não for especificado

A arrow function (fn() =>) é uma sintaxe compacta do PHP 7.4+ para funções de uma linha que capturam variáveis do escopo externo automaticamente (sem precisar de use).

20 O que é in_array()? Como é usado para controle de acesso? ▼

in_array(valor, array) verifica se um valor existe dentro de um array. Retorna true ou false.

// Controle de acesso — index.php
$paginasPublicas = ["home", "noticias", "sobre", "login", "registro", "recuperar"];

if (!$autenticado && !in_array($page, $paginasPublicas)) {
    header("Location: ./?p=login");
    exit;
}

// Validação de valores aceitos — Model Tarefa
if (!in_array($status, ["pendente", "em_andamento", "concluida"])) {
    throw new \InvalidArgumentException("Status inválido.");
}

// Validação de cargo — Model Usuario
if (!in_array($cargo, ["admin", "membro"])) {
    throw new \InvalidArgumentException("Cargo inválido.");
}

É uma whitelist (lista branca): em vez de tentar bloquear valores inválidos, definimos exatamente quais são válidos.

23 O que faz <meta charset="UTF-8"> e <meta name="viewport">? ▼

</head>

25 O que é <input type="hidden"> e onde é usado no projeto? ▼

Um campo invisível para o usuário mas enviado junto com o formulário no POST. O usuário não vê, mas o servidor recebe.

Usado em três situações no projeto:

  • Token CSRF: <input type="hidden" name="csrf" value="..."> — protege contra ataques cross-site
  • ID do registro: <input type="hidden" name="id" value="..."> — ao editar, informa qual registro atualizar
  • criado_por: <input type="hidden" name="criado_por" value="..."> — mantém o autor original ao editar tarefa
<!-- Formulário de edição de tarefa -->
<form action="./?p=alt-tarefa" method="post">
  <input type="hidden" name="csrf"       value="<?= $_SESSION['csrf_token'] ?>">
  <input type="hidden" name="id"         value="<?= $tarefa->getId() ?>">
  <input type="hidden" name="criado_por" value="<?= $tarefa->getCriadoPor() ?>">
  ...
</form>
26 O que faz o atributo action no <form>? O que acontece se omitir? ▼

action define para qual URL os dados do formulário serão enviados. Se omitido, o formulário envia para a URL atual (mesma página).

<!-- Envia para ?p=login (mesma page do formulário) -->
<form action="./?p=login" method="post">

<!-- Envia para ?p=alt-tarefa -->
<form action="./?p=alt-tarefa" method="post">

<!-- Sem action = envia pra URL atual -->
<form method="post">

No projeto usamos action="./?p=..." explícito para ficar claro qual controller vai processar. O controller identifica se é POST ou GET pelo $_SERVER["REQUEST_METHOD"].

27 O que é <label for=""> e por que é importante? ▼

<label for="id"> associa um texto descritivo a um campo de formulário. O for deve ter o mesmo valor do id do input correspondente.

Por que é importante:

  • Acessibilidade: leitores de tela anunciam o label quando o campo recebe foco
  • Usabilidade: clicar no label foca/ativa o campo automaticamente
  • Semântica: deixa explícita a relação entre texto e campo
<!-- Correto: label vinculado ao input pelo id -->
<label for="email">E-mail</label>
<input type="text" name="email" id="email">

<!-- Ao clicar em "E-mail", o cursor vai pro campo -->
28 Como funciona o <select> com <option>? Como o selected é definido dinamicamente? ▼

<select> cria uma lista suspensa. Cada opção é um <option value="...">. O atributo selected marca qual opção está pré-selecionada.

No projeto, o status atual da tarefa é pré-selecionado com PHP ternário:

<select name="status" id="status">
  <option value="pendente"
    <?= $tarefa->getStatus() === "pendente" ? "selected" : "" ?>>
    Pendente
  </option>
  <option value="em_andamento"
    <?= $tarefa->getStatus() === "em_andamento" ? "selected" : "" ?>>
    Em andamento
  </option>
  <option value="concluida"
    <?= $tarefa->getStatus() === "concluida" ? "selected" : "" ?>>
    Concluída
  </option>
</select>

O operador ternário condição ? "selected" : "" escreve selected apenas na opção que bate com o status salvo no banco.

31 O que é declare(strict_types=1)? Por que está no início dos arquivos? ▼

Ativa a verificação estrita de tipos no PHP. Sem isso, o PHP faz conversões automáticas silenciosas que podem causar bugs difíceis de encontrar.

// Sem strict_types: PHP converte silenciosamente
function somar(int $a, int $b): int { return $a + $b; }
somar("3", "4"); // funciona, PHP converte string pra int

// Com strict_types=1: PHP lança TypeError
declare(strict_types=1);
somar("3", "4"); // TypeError: deve ser int, não string

Deve ser a primeira linha do arquivo (depois de <?php). Se vier depois de qualquer instrução, causa um erro fatal.

Obriga que os tipos declarados nos parâmetros e retornos das funções sejam respeitados — os bugs aparecem cedo, na hora do desenvolvimento, não em produção.
32 O que faz preg_replace('/\D/', '', $cpf)? ▼

preg_replace substitui partes de uma string que casam com uma expressão regular.

  • /\D/ — padrão regex: "qualquer caractere que NÃO seja dígito" (\D = não-dígito)
  • '' — substitui pelo vazio (remove)
  • Resultado: sobram apenas os números
// Usuario::setCpf() — normaliza CPF antes de validar
$cpf = preg_replace('/\D/', '', $cpf);
// "123.456.789-09"  →  "12345678909"
// "123 456 789 09"  →  "12345678909"
// "12345678909"     →  "12345678909" (sem mudança)

if (strlen($cpf) !== 11) {
    throw new \InvalidArgumentException("O CPF deve ter 11 dígitos.");
}

Assim o sistema aceita CPF com ou sem formatação e armazena sempre limpo (só números).

33 O que é try/catch/throw e como funciona no projeto? ▼

Mecanismo de tratamento de erros em POO:

  • throw — lança uma exceção (para a execução normal)
  • try — bloco onde exceções podem ocorrer
  • catch — captura a exceção e define o que fazer
// No Model: lança exceção se dado inválido
public function setNome(string $nome): void {
    if ($nome === "") {
        throw new \InvalidArgumentException("O nome é obrigatório.");
    }
    $this->nome = $nome;
}

// No Controller: captura a exceção e exibe mensagem
try {
    $usuario = Usuario::criar(null, $nome, $email, ...);
    UsuarioDao::cadastrar($usuario);
    header("Location: ./?p=login"); exit;
} catch (Exception $e) {
    self::$msg = $e->getMessage(); // "O nome é obrigatório."
}
// Sem o try/catch, a exceção quebraria a página inteira

O PDOException (erro de banco) também é capturado com catch (PDOException $e) nos DAOs e relançado para o Controller tratar.

34 O que é rowCount() e onde é usado? ▼

rowCount() retorna o número de linhas afetadas pela última instrução SQL (INSERT, UPDATE, DELETE). Usado para verificar se a operação realmente funcionou.

// TarefaDao::editar() — verifica se o UPDATE alterou algo
$sql->execute([...]);
if ($sql->rowCount() !== 1) {
    throw new Exception("Nenhum registro foi alterado.");
}

// Por que verificar? Se o id não existir no banco,
// o UPDATE roda sem erros mas não afeta nenhuma linha.
// rowCount() == 0 nos avisa disso.
35 O que é lastInsertId() e quando é usado? ▼

Após um INSERT, lastInsertId() retorna o valor do AUTO_INCREMENT gerado para o registro recém-inserido. É chamado no objeto PDO, não no statement.

// UsuarioDao::cadastrar() — retorna o id do novo usuário
$sql->execute();
return (int) $pdo->lastInsertId();
//              ↑ é $pdo, não $sql

Isso permite que o Controller saiba qual id foi criado, caso precise usar logo em seguida (ex: criar tarefa vinculada ao usuário recém-criado).

36 O que é o operador ?? (null coalescing)? Como está no projeto? ▼

$a ?? $b retorna $a se ela existir e não for null, senão retorna $b. É um atalho para isset($a) ? $a : $b.

// Leitura segura de parâmetros que podem não existir
$page  = $_GET["p"]      ?? "home";   // default: home
$email = $_POST["email"] ?? "";       // default: string vazia
$cargo = $_SESSION["cargo"] ?? "";    // default: string vazia

// Evita o erro: "Undefined index: p"
// Sem ??: if (isset($_GET["p"])) { $page = $_GET["p"]; } else { $page = "home"; }

// Encadeamento: tenta a, depois b, depois c
$dados["descricao"] ?? ""  // se descricao não vier do banco, usa ""

39 O que é encapsulamento em POO e como está aplicado nos Models? ▼

Encapsulamento é o princípio de esconder os dados internos de uma classe e controlar o acesso por métodos públicos. Os atributos ficam private e só são acessados/modificados de forma controlada.

No projeto:

  • Todos os atributos dos Models são private — ninguém de fora mexe diretamente
  • Getters públicos permitem apenas leitura
  • Setters privados validam o dado antes de gravar
class Usuario {
    private string $cpf;  // ← ninguém acessa diretamente

    // Getter público: só leitura
    public function getCpf(): string { return $this->cpf; }

    // Setter privado: valida e grava
    private function setCpf(string $cpf): void {
        $cpf = preg_replace('/\D/', '', $cpf);
        if (strlen($cpf) !== 11)
            throw new \InvalidArgumentException("CPF inválido.");
        $this->cpf = $cpf;  // só chega aqui se válido
    }
}

// De fora:
$u->cpf = "123";           // ERRO — private
$u->getCpf();              // OK — getter público
$u = Usuario::criar(null, ..., "123.456.789-09", ...); // setCpf chamado internamente

Toda vez que o PHP encontra uma classe ainda não carregada, chama a função registrada aqui, que converte o namespace em caminho de arquivo e faz o require_once.

spl_autoload_register(function ($namespace) {
    // "App\Controller\AuthController"
    // → remove "App\"  → "Controller\AuthController"
    // → troca "\" por "/"  → "Controller/AuthController"
    // → adiciona ".php"  → "Controller/AuthController.php"
    $arquivo = __DIR__ . DIRECTORY_SEPARATOR
        . str_replace(['App\\', '\\'], ['', DIRECTORY_SEPARATOR], $namespace)

Conexão com o banco — Padrão Singleton

O padrão Singleton garante que a conexão com o banco seja criada apenas uma vez por requisição, mesmo que vários DAOs a solicitem.

  • private static ?PDO $conn = null — armazena a instância única
  • getConn() — se $conn for nula, cria; senão retorna a existente
abstract class Conn {
    private static ?PDO $conn = null;

    public static function getConn(): PDO {
        if (self::$conn === null) {         // só conecta na 1ª chamada
            self::$conn = new PDO(
                "mysql:host=localhost:3307;dbname=palmeirasdb",
                "root", ""
            );
        }
        return self::$conn;         // retorna sempre a mesma
    }
}

        $t->setStatus($status);   // valida: deve estar na whitelist
        return $t;
    }

    public function setStatus(string $status): void {
        if (!in_array($status, ["pendente", "em_andamento", "concluida"])) {
            throw new \InvalidArgumentException("Status inválido.");
        }
        $this->status = $status;

// Estrutura padrão de um método de controller
public static function cadastrar(): void {
    // 1. Verificar permissão
    if ($_SESSION["cargo"] !== "admin") {
        header("Location: ./?p=tarefas"); exit;
    }

    // 2. Processar POST se formulário foi enviado
    if ($_SERVER["REQUEST_METHOD"] === "POST" && isset($_POST["titulo"])) {
        // 3. Validar CSRF
        if (!hash_equals($_SESSION["csrf_token"], $_POST["csrf"] ?? "")) {
            die("Falha no acesso");
        }
        // 4. Sanitizar dados
        $titulo = Util::preparaTexto($_POST["titulo"]);
        // 5. Criar objeto Model + chamar DAO
        try {
            $tarefa = Tarefa::criar(null, $titulo, ...);
            TarefaDao::cadastrar($tarefa);
            header("Location: ./?p=tarefas"); exit;
        } catch (Exception $e) {
            self::$msg = $e->getMessage();
        }
    }
    // 6. Exibe o formulário (GET ou erro no POST)
    TarefaView::formulario(self::$msg, null, $usuarios);
}

Proteção CSRF — ciclo completo
index.php → Views → Controllers
1 index.php: $_SESSION["csrf_token"] = bin2hex(random_bytes(32))
2 View inclui: <input type="hidden" name="csrf" value="...">
3 Usuário envia formulário — token vai junto no POST
4 Controller: hash_equals($_SESSION["csrf_token"], $_POST["csrf"])
5 Não bater → die("Falha no acesso")
Um site externo que tente enviar um POST para o nosso sistema não terá o token correto — porque o token fica na sessão do usuário no servidor, não no HTML público.

Cookie "lembrar-me" — como persiste o login
controller/AuthController.php → dal/UsuarioDao.php
1 Login com "lembrar-me" marcado
2 Gera: $tokenRaw = bin2hex(random_bytes(32)) — 64 chars hex aleatórios
3 Calcula: $hashToken = hash("sha256", $tokenRaw)
4 Salva $hashToken na coluna token_lembrar do banco
5 Envia $tokenRaw no cookie por 30 dias
6 Próxima visita: lê cookie → calcula sha256 → busca no banco → loga
7 Logout: zera o token no banco + apaga o cookie
// setcookie(nome, valor, expira, path, dominio, https, httponly)
setcookie("palmeiras_token", $tokenRaw, $expira, "/", "", false, true);
//                                                         ↑
//                                                    httponly=true
//                             Impede JavaScript de ler o cookie (proteção XSS)

Recuperação de senha — dois passos com sessão
controller/AuthController::recuperar()

Como não há envio de e-mail, a identidade é provada com e-mail + CPF + data de nascimento. O processo usa a sessão como "memória temporária":

Etapa 1 Usuário entra com e-mail, CPF e nascimento
→ Controller busca usuário pelo e-mail no banco
→ Compara CPF e data de nascimento com o cadastro
→ Se bater: $_SESSION["recuperar_id"] = $usuario->getId()
→ Exibe formulário da Etapa 2 (nova senha)
Etapa 2 Usuário digita nova senha + confirmação
→ Controller lê $_SESSION["recuperar_id"] para saber qual usuário
→ Chama UsuarioDao::atualizarSenha($id, password_hash($nova))
→ Remove recuperar_id da sessão + redireciona ao login
O $_SESSION["recuperar_id"] funciona como uma "chave temporária" — só existe enquanto a sessão estiver ativa e é removido após o uso, impedindo que o mesmo fluxo seja reutilizado.
